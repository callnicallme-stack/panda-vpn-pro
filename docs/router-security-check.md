# 路由器 Telnet / SSH 暴露安全检查指南

> **重要声明**
>
> 本指南仅用于帮助设备**拥有者**对**自己管理下的局域网设备**进行安全验证，所有步骤均为**无损、非入侵性**的检测操作。
> 本指南**不提供任何漏洞利用、暴力破解或未授权访问方法**。若你并非所检测设备的合法拥有者，请立即停止。

---

## 背景：为什么 4G 路由器的 Telnet / SSH 暴露值得关注

当你使用 VPN / 代理工具（如本项目推荐的各类机场方案）翻墙时，**流量先经过本地路由器再到达 VPN 服务器**。
若路由器本身存在以下安全风险，VPN 层面的保护可能被绕过：

- Telnet（端口 23）以明文传输，无加密，任何同网段设备均可嗅探。
- SSH（端口 22）若使用弱默认口令或对外网开放，攻击者可获取 root shell。
- 某些低成本 4G 路由器预置了厂商云管理后门，或默认开启 Telnet/SSH 且口令固定。

## 安全检查步骤（适用于局域网，如 192.168.0.1）

### 第 1 步：通过路由器管理界面确认已开启的服务（推荐首先执行）

1. 在浏览器中打开 `http://192.168.0.1`（或路由器实际的管理地址）。
2. 使用管理员账号登录。
3. 在以下菜单中检查是否存在并已启用对应服务：

   | 关注项 | 说明 |
   |---|---|
   | Telnet | 若"已启用"，应立即关闭（明文协议，安全性极低） |
   | SSH | 若对 WAN 或所有接口开放，应限制为仅 LAN |
   | 远程管理 / Remote Management | 若已启用，确认是否只允许局域网访问 |
   | TR-069 / ACS | 运营商远程管理协议，家用场景一般可关闭 |
   | UPnP | 若不需要，建议关闭以减小攻击面 |
   | 自动固件升级 | 了解升级服务器地址，确认来源可信 |

---

### 第 2 步：在局域网内扫描开放端口（安全端口扫描）

> **工具要求**：[nmap](https://nmap.org/)（Windows / macOS / Linux 均可安装）

在与路由器同一局域网的设备上执行：

```bash
# 仅检测 SSH（22）和 Telnet（23）端口
nmap -sV -p 22,23 192.168.0.1
```

**预期输出示例（未开放）：**

```
PORT   STATE  SERVICE
22/tcp closed ssh
23/tcp closed telnet
```

**预期输出示例（已开放）：**

```
PORT   STATE SERVICE VERSION
22/tcp open  ssh     Dropbear sshd 2019.78
23/tcp open  telnet
```

若 `STATE` 为 `open`，继续执行第 3 步确认。

> 补充：若需同时扫描更多常见管理端口，可使用：
> ```bash
> nmap -sV -p 22,23,80,443,7547,8080,8443 192.168.0.1
> ```
> - `7547` — TR-069 常见端口
> - `8080` / `8443` — 部分路由器使用的备用管理端口

---

### 第 3 步：验证 Telnet 是否可以连接（仅确认服务存在）

> **目的**：确认端口扫描结果，观察服务的登录提示（Banner）。
> **注意**：仅连接并查看提示信息，**不要尝试任何密码猜测**。

```bash
# Windows（命令提示符，需先启用 Telnet 客户端功能）
telnet 192.168.0.1

# macOS / Linux
telnet 192.168.0.1 23
```

**典型的响应（表示 Telnet 服务开放）：**

```
Trying 192.168.0.1...
Connected to 192.168.0.1.
Escape character is '^]'.

login:
```

观察到登录提示后，按 `Ctrl + ]`，再输入 `quit` 退出，**不要继续输入账号或密码**。

---

### 第 4 步：验证 SSH 是否可以连接（仅确认服务存在）

> **目的**：确认端口扫描结果，获取 SSH 服务的版本 Banner。
> **注意**：仅连接并查看 Banner，**不要尝试任何认证**。

```bash
# macOS / Linux
ssh -v 192.168.0.1 2>&1 | head -20

# Windows（PowerShell，需安装 OpenSSH 客户端）
ssh -v 192.168.0.1 2>&1 | Select-Object -First 20
```

**典型的响应（表示 SSH 服务开放）：**

```
OpenSSH_9.x, ...
debug1: Connecting to 192.168.0.1 [192.168.0.1] port 22.
debug1: Connection established.
debug1: Remote protocol version 2.0, remote software version Dropbear_2019.78
```

看到 SSH Banner 后按 `Ctrl + C` 中断即可，无需进行任何登录操作。

---

### 第 5 步：观察路由器的主动外联行为（进阶，可选）

> 若怀疑设备与未知服务器保持长连接，可在上级网络设备（如光猫或另一台路由器）查看 DNS 请求日志，或使用以下工具抓包分析。

**在路由器上（若可 SSH 登录）：**

```bash
# 查看当前所有建立的连接
netstat -an | grep ESTABLISHED

# 查看已建立的 TCP 连接（含进程）
ss -tnp
```

**在电脑上通过 Wireshark 分析 WAN 侧流量：**

- 抓取路由器的 WAN 接口流量（若上级设备支持端口镜像）。
- 过滤规则：`ip.dst != 192.168.0.0/24 && ip.src == 192.168.0.1`
- 重点关注：高频心跳包、固定目标 IP / 域名的长连接、异常的夜间上传流量。

## 发现 Telnet / SSH 开放后的建议操作

| 情况 | 建议操作 |
|---|---|
| Telnet 开放 | 在管理界面关闭，该协议无加密，不应在任何场景下开放 |
| SSH 仅对 LAN 开放，口令为默认值 | 立即更改 SSH 密码或改为密钥认证 |
| SSH 对 WAN 开放 | 关闭对外开放，或限制为仅允许固定 IP 访问 |
| 无法在管理界面关闭 Telnet/SSH | 考虑刷写可信第三方固件（如 OpenWrt），或在上级防火墙中拦截该端口 |
| 发现不明外联服务器 | 对出站流量增加防火墙规则，或更换设备 |

## 与使用代理 / VPN 的关系

若你使用本项目推荐的机场服务：

1. **路由器若被控制，攻击者可在 VPN 建立前捕获流量**，或修改 DNS 将你的流量重定向至恶意服务器。
2. 建议确保路由器处于安全状态后，再依赖 VPN / 代理的安全保护。
3. 若希望进一步隔离风险，可考虑在路由器后加一层运行 OpenWrt 的软路由，由软路由统一管理代理出口。

## 常见问题

**Q：nmap 是否会损坏路由器？**  
A：`nmap -sV -p 22,23` 发送的是标准 TCP SYN 探测包，属于正常网络请求，不会对路由器造成任何损坏。

**Q：仅连接 Telnet / SSH 查看登录提示是否构成违法？**  
A：对自己管理的设备进行连通性验证是完全合法的。若设备不属于你，则应立即停止。

**Q：扫描发现端口 open，但我无法关闭它怎么办？**  
A：可在上级路由器（光猫或另一台路由器）的防火墙中，对目的端口 22/23 添加入站阻断规则，从网络层面隔离该服务。
